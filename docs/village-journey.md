# 입력부터 결과까지 이어지는 마을

배치 마을과 분석 마을은 `village-world.mjs`의 같은 레고 모델·카메라 구현을 사용한다. 상세 입력에서는 해당 카테고리를 확대하고 입력 확인에서는 마을 전체를 보여준다. 건물 위치로 계산한 중요도는 카메라 이동과 무관하다. 배치로 돌아가면 원래 배치용 확대 배율을 복원한다.

조건 확인을 승인하면 약1초 동안 건물에서 중앙 집으로 신호가 모인다. 그다음 실제 후보 조회·비교를 시작한다. 이 연출은 처리 완료율을 뜻하지 않는다. 비교 요청의 선택적 `progress_id`와 같은 세션의 `/api/progress/{id}`는 실제 오케스트레이터의 모듈/참고 조회 시작·종료 이벤트만 전달한다. 기존 비교 API 입력도 유지된다. 아주 빠른 공공 조회는 중간 단계가 화면에 오래 보이지 않을 수 있다.

분야별 상태는 선택 안 함/조건 정리/대기/진행 중/완료/일부 미확인/실패/취소/미실행이다. 선택 안 한 분야는 여섯 칸 안에서 흐리게 표시한다. 활성 건물은 대기 중 반투명, 진행 중 숨쉬듯 진해지고 실제 완료 뒤 완전히 선명해진다. 원문 검증 실패·자료 미확인·미실행 보완 조사를 완료로 바꾸지 않는다. 일부 상태는 전체 조건 충족을 뜻하지 않는다.

웹 보완은 실제 요청별 상태를 사용한다. 조사 중에도 취소 버튼을 사용할 수 있고 취소 뒤 공공 결과는 유지한다. 모든 요청이 종료된 뒤 중앙 집을 확대하고 지도·비교 결과를 표시한다. 참고만 요청한 취미 조사의 범위 전달 공백은 별도 남은 문제이며 화면 연출로 해결한 것은 아니다.

모바일은 마을 위/질문 아래로 배치하고, 작은 상태 표시 여섯 개를 두 줄로 나눈다. 동작 감소 설정에서는 카메라·건물 상태를 즉시 반영하고 반복 움직임/연출 대기를 생략한다. WebGL을 사용할 수 없어도 분석 화면의 상태와 결과는 표시한다. 숨긴 진단 출력에는 카메라 목표·배율·건물 투명도·좌표를 제공해 실제 화면과 상태를 대조할 수 있다.
