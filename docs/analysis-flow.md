# 새 분석 흐름

2026-10-01. 기본 화면은 `/` → `/analysis`다. `/workspace`는 기존 상세 편집 화면으로 남아 있다.

## 진입과 분석

- **주소 없이 찾아보기**: 진주 전체 또는 준비된 읍면동 이름 → 블록 배치 → 선택 분야 상세 입력 → 니즈 정리/필요 인터뷰 → 공통 분석 지점 탐색 → 지도 결과.
- **집 한 곳 분석**: 집 이름·동네 메모 → 배치/상세/니즈 정리 → 지도에서 위치 선택 → 단독 분석. 결과의 ‘주변 비교 추가’로 후보를 추가한다.
- **여러 집 비교**: 같은 입력 흐름 뒤 지도에서 2~6곳을 직접 선택한다.

집 위치는 지도 클릭 또는 좌표 입력으로 지정한다. 메모를 주소로 변환하는 기능은 없다. 알려진 집의 메모·좌표는 니즈 정리용 모델 프롬프트에 넣지 않는다. 탐색 읍면동 이름과 정성 보완에 필요한 공공 시설·지역 정보는 해당 조사에 사용한다.

상세 입력 뒤 니즈 정리는 자동 실행된다. 확인할 개인 기준이 남으면 최대 3개 질문을 보여준다. 사용자가 진행을 승인하면 미확인 조건을 보존하고 탐색한다. 전송 실패/취소 시 초안은 탭에 남는다. 다시 분석하면 실제 모델 작업을 다시 요청한다. 서버의 동시 모델 작업은 1개이며 다른 작업 중에는 시작할 수 없다.

## 계약과 근거

LLM은 간결한 `IntakeDraft`와 근거 문장 ID를 반환한다. 원 요청·개정 번호·분야 이름·정확한 원문은 앱이 붙인다. 보조 파라미터 키는 최종 계약과 동일한 12개로 제한한다. 근거 ID, 기존 조건 ID, 명시된 좌표와 필수조건을 검사하며 검사를 통과하지 못한 응답을 비교에 사용하지 않는다. 안전한 오류 종류/필드 위치와 실행 시간만 진단 메타데이터로 남기며 원시 모델 이벤트·계정 정보는 저장하지 않는다.

집·비용은 점수 0인 실거래 참고다. 집값만 선택한 참고 조회도 허용한다. 나머지 선택 분야의 배치 중요도를 정규화하며 집·비용 블록에는 ‘참고’를 표시한다. 도보 분을 직선거리로 환산하거나 안전/취미 평가를 CCTV 수·시설 수로 대신하지 않는다.

공통 탐색 계획은 생활/정류장/학교/학원/공원/도서관/직접 지정 만남 지표와 미확인 지표를 구분한다. 기본 API의 `strict`는 모든 활성 근거가 확인된 지점만 선별한다. 새 화면의 `exploratory`는 비필수 미확인 조건의 비중을 유지하고 확인한 기여가 큰 지점을 보여주되 전체 순위를 보류한다. 미지원 필수조건은 탐색을 중단한다. 탐색 중에는 대규모 CCTV·가격 참고 결과를 붙이지 않고 최종 선택 이후 조회한다.

## 결과와 제한

결과는 지도, 점수/가능 범위, 확인 가능한 비중, 분야별 기여, 조건과 출처로 구성한다. 집 한 곳에는 후보 간 우열 표현을 쓰지 않는다. 필수조건 탈락 후보도 결과에서 표시한다. 집값 참고와 요청된 웹 보완은 별도 영역에 둔다. 실제 원문·작성일·지점/종목 검사를 통과한 짧은 인용만 보여주며, 작성일 없는 운영자 발견 후보는 인용과 구분한다. 보완 실패/취소가 공공자료 결과를 지우지 않는다.

분석 지점은 상가가 등록된 500m 격자의 중심이다. 실제 집·매물·거주 가능성이 확인된 위치가 아니다. 가격 참고의 기본 범위는 진주 전체/전체 면적이며 개별 집의 가격으로 해석하지 않는다. 법정동/면적의 상세 참고 필터는 기존 `/workspace`에서 사용할 수 있다. 실제 도보/통근 경로·학교 배정·현재 시설 이용·정량 안전/취미 품질·모든 입력 조합·실휴대폰·실사용 효과는 별도 검증 대상이다.
