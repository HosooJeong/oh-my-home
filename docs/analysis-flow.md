# 새 분석 흐름

2026-10-01. 기본 화면은 `/` → `/analysis`다. `/workspace`는 기존 상세 편집 화면으로 남아 있다.

## 진입과 분석

- **주소 없이 찾아보기**: 진주 전체 또는 준비된 읍면동 이름 → 블록 배치 → 선택 분야 상세 입력 → 니즈 정리/필요 인터뷰 → 공통 분석 지점 탐색 → 지도 결과.
- **집 한 곳 분석**: 집 이름·동네 메모 → 배치/상세/니즈 정리 → 지도에서 위치 선택 → 단독 분석. 결과의 ‘주변 비교 추가’로 후보를 추가한다.
- **여러 집 비교**: 같은 입력 흐름 뒤 지도에서 2~6곳을 직접 선택한다.

집 위치는 지도 클릭 또는 좌표 입력으로 지정한다. 메모를 주소로 변환하는 기능은 없다. 알려진 집의 메모·좌표는 니즈 정리용 모델 프롬프트에 넣지 않는다. 탐색 읍면동 이름과 정성 보완에 필요한 공공 시설·지역 정보는 해당 조사에 사용한다.

상세 입력 뒤 니즈 정리는 자동 실행된다. 확인할 개인 기준이 남으면 한 화면에 최대 3개 질문을 보여준다. 진행을 막는 질문을 먼저 보여주며 나머지는 프로필에 보존한다. 사용자가 진행을 승인하면 미확인 조건을 보존하고 탐색한다. 전송 실패/취소 시 초안은 탭에 남는다. 다시 분석하면 실제 모델 작업을 다시 요청한다. 서버의 동시 모델 작업은 1개이며 다른 작업 중에는 시작할 수 없다.

니즈 정리 결과에 배치하지 않은 분야나 추가 요구가 있으면 조건·필수조건·질문을 보존하고 포함 여부를 먼저 확인한다. 확인 화면은 추가 요구의 원문과 필수 표시, 포함·제외에 따른 실제 분야 비중을 보여준다. 사용자가 제외한 분야의 조건과 해당 질문만 제거하며, 여러 조건에 걸친 질문은 남은 조건에 연결한다. 추가 분야의 포함 확인은 R1이며, 자연어 요구의 누락·축약 검사는 아래 R2의 별도 정리 단계에서 수행한다.

`/workspace`의 생활 간편 입력과 교통·교육·안전·여가 편집은 실제로 수정한 항목을 `edited_fields`로 전달한다. 시간대·중요도 변경은 기존 필수거리·학교 ID·시설별 거리 곡선·상세 안전 요구를 바꾸지 않는다. 정류장의 필수 최대 거리와 만족도 0 거리는 별개다. 여가의 공통 거리 입력을 직접 수정하면 선택한 공원·도서관·만남 지점에 함께 적용한다. 같은 입력란에 여러 사람의 동선이 있거나 기존 단위/방향을 표현할 수 없으면 원래 프로필을 보존하고 수정 이유를 안내한다. 사람별 전용 편집 기능은 아직 없다.

취미 조사 입력은 조건 ID별 종목명과 이용 형태를 한 쌍으로 유지한다. 한 번에 조건 요청 최대 3개/시설 최대 6곳을 조사하며, 범위 밖 조건도 프로필에 남기고 미조사 목록으로 반환한다. 같은 종목 코드로 여러 요청이 있으면 조건 ID가 없는 응답을 임의로 연결하지 않는다. 이용 형태의 실제 원문 검증 강화는 후속 작업이다.

## 계약과 근거

LLM은 간결한 `IntakeDraft`와 근거 문장 ID를 반환한다. 원 요청·개정 번호·분야 이름·정확한 원문은 앱이 붙인다. 보조 파라미터 키는 최종 계약과 동일한 12개로 제한한다. 근거 ID, 기존 조건 ID, 명시된 좌표와 필수조건을 검사하며 검사를 통과하지 못한 응답을 비교에 사용하지 않는다. 안전한 오류 종류/필드 위치와 실행 시간만 진단 메타데이터로 남기며 원시 모델 이벤트·계정 정보는 저장하지 않는다.

집·비용은 점수 0인 실거래 참고다. 집값만 선택한 참고 조회도 허용한다. 나머지 선택 분야의 배치 중요도를 정규화하며 집·비용 블록에는 ‘참고’를 표시한다. 도보 분을 직선거리로 환산하거나 안전/취미 평가를 CCTV 수·시설 수로 대신하지 않는다.

공통 탐색 계획은 생활/정류장/학교/학원/공원/도서관/직접 지정 만남 지표와 미확인 지표를 구분한다. 기본 API의 `strict`는 모든 활성 근거가 확인된 지점만 선별한다. 새 화면의 `exploratory`는 비필수 미확인 조건의 비중을 유지하고 확인한 기여가 큰 지점을 보여주되 전체 순위를 보류한다. 미지원 필수조건은 탐색을 중단한다. 탐색 중에는 대규모 CCTV·가격 참고 결과를 붙이지 않고 최종 선택 이후 조회한다.

## 결과와 제한

결과는 지도, 점수/가능 범위, 확인 가능한 비중, 분야별 기여, 조건과 출처로 구성한다. 집 한 곳에는 후보 간 우열 표현을 쓰지 않는다. 필수조건 탈락 후보도 결과에서 표시한다. 집값 참고와 요청된 웹 보완은 별도 영역에 둔다. 실제 원문·작성일·지점/종목 검사를 통과한 짧은 인용만 보여주며, 작성일 없는 운영자 발견 후보는 인용과 구분한다. 보완 실패/취소가 공공자료 결과를 지우지 않는다.

분석 지점은 상가가 등록된 500m 격자의 중심이다. 실제 집·매물·거주 가능성이 확인된 위치가 아니다. 가격 참고의 기본 범위는 진주 전체/전체 면적이며 개별 집의 가격으로 해석하지 않는다. 법정동/면적의 상세 참고 필터는 기존 `/workspace`에서 사용할 수 있다. 실제 도보/통근 경로·학교 배정·현재 시설 이용·정량 안전/취미 품질·모든 입력 조합·실휴대폰·실사용 효과는 별도 검증 대상이다.

개발 증거와 기준 기록은 상위 `AIcontest/docs/project-records/` 및 `work/saljari-evidence/20261001/`에 보관한다. 배포/최종 제출본과 개발본을 구분한다.

## R2 원문 요구의 처리 확인

`IntakeDraft.needs`는 원문 문장 ID별로 비교·보완 조사·참고·배경·명시 제외·추가 확인을 구분하고, 조건 ID 또는 맥락 키에 연결한다. 실제 연결이 없거나 다른 원문의 조건/맥락을 가져온 응답, 근거 없는 제외를 수용하지 않는다. 원문·조건 ID의 기존 검사를 유지하며 최종 `NeedProfile` 공개 계약은 바꾸지 않았다. 처리표는 정리 단계 내부 정보이고 안전한 처리 수/복원 수만 진단에 남긴다.

직선거리 지표는 직선거리만, 학원 개소 지표는 등록 개소만 다룬다. 연결한 요구 유형이 다르면 정확한 원문 요구를 별도 미지원 조건으로 보존한다. 큰 마트·대량 장보기/규모·품목·시설 이용 형태, 실제 도보·통근시간·환승·학교 배정·횡단/야간/침수/소음은 검토에서 확인한 사례에 대한 제한된 보조 검사도 적용한다. 빠진 원문은 맥락으로 남기고 짧은 차단 질문을 추가한다. `clarify`인데 질문이 빠진 경우에도 확인을 요청한다.

명시 필수인 미지원 조건은 원래 문장 전체의 충족 여부를 boolean 조건으로 보존할 수 있다. 실제 이동시간·품질의 만족도 곡선을 임의로 만드는 기능은 아니다. 모듈에서 확인할 근거가 없으면 필수 여부와 점수 비중을 유지한 채 미확인/전체 순위 보류로 반환한다. 복원 조건의 중요도는 사용자 확정값으로 주장하지 않고 제안 상태로 확인한다. 화면에는 원문 또는 조건 설명과 미확인/필수조건 미확인을 표시하고 `1bool 목표`를 노출하지 않는다.

단순 후기 인용·참고 조회와 배경 사실은 비교 점수로 만들지 않는다. 보완 조사 처리는 요청 플래그와의 연결을 확인하지만 실제 질문을 조사에 전달하고 모든 요청의 실행 상태를 반환하는 것은 R3 범위다. 이번은 문장별 대응과 제한된 유형 검사이며 모든 자연어 의미의 정확성을 입증한 것은 아니다. 한 문장 내부의 모든 요구 누락·잘못된 유형 분류/제외 대상을 완벽히 검출하지 않으며 실제 모델의 오류 빈도·실사용 효과는 미측정이다.

R2 검증은 상위 `work/saljari-evidence/20261001/r2-validation.json`에 연결한다. 새 응답 형식의 실제 모델 확인은 개인정보 없는 합성 요청 1회이며, 브라우저 인터뷰는 별도 오프라인 fixture다.
