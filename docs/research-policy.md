# 공공 근거와 LLM 보완 조사 기준

2026-09-30 사용자 확정: 검증된/공공데이터가 있으면 우선 사용하고, 정성적 설명이나 판단에 필요한 보완은 LLM을 파이프라인에 넣어 직접 검색한다. 오래되거나 부정확한 자료는 배제한다. 숫자 기간·검사 방법·현재 제공처 범위는 구현 선택이며 사용자 개인 선호가 아니다.

1. 공식 조회로 확인된 거리·수·등록 정보는 프로그램이 계산한다. LLM이 데이터 공백을 숫자로 채우거나 다른 분야로 가중치를 옮기지 않는다.
2. 니즈 정리에서는 검색을 끈다. 보완 요청이 있을 때 비교 뒤 웹 조사 작업을 시작한다. 현재 M1 상가/M4 학원에 연결했고 M2 경로·M5/M6 전용 조사는 아직 구현하지 않았다. 재가중치는 추가 검색 없이 수행한다.
3. 시설의 변하기 쉬운 정성 정보는 작성 **730일 이내**를 초기 허용 기간으로 사용한다. 실제 원문의 작성일 메타데이터/Article JSON-LD와 대조한다. 수정일·수집일로 작성일을 대체하지 않는다. 작성일 없음/여러 게시일 충돌/미래/기간 밖이면 제외한다. 필요하면 분야별 정책을 추가한다.
4. LLM이 직접 검색/원문을 읽고 URL·작성일·짧은 원문 인용·해석·같은 시설 근거를 반환한다. 서버가 원문을 다시 읽어 시설명과 도로명 주소, 인용 문구를 대조한다. 검색 요약/접근 불가/다른 지점/협찬·체험단 표시/조작된 인용은 제외한다. 출처당 20단어, 인용 160자, 시설당 최대 2개다.
5. 공식 정보·일부 작성자의 경험·AI 해석·미확인을 구분한다. 후기 몇 건을 전체 만족도/현재 상태/객관적 품질로 일반화하지 않는다. 원문 문구 대조는 모든 주장에 대한 사실검증이나 독립성 보장이 아니다.
6. 결과는 메인에 별도 정성 근거로 모인다. 정량 점수·순위·필수조건 통과 근거로 자동 승격하지 않는다. 인용 가능 자료가 없으면 빈 결과로 남긴다.

`app/research_policy.py`가 공통 프롬프트와 원문 수용 검사를 관리한다. 현재 공개 원문 제공처는 기존 티스토리 연결을 유지한다. robots.txt·크기/시간 제한·링크 검사·공공 시설명/주소만 전달하는 범위를 지키며 카카오/네이버 Local 응답·지도 리뷰·사용자 위치/개인 입력·키를 조사 모델에 전송하지 않는다. 제공처 확장 시 원문 접근·권리·작성일/동일 시설 식별을 확인한 뒤 추가한다. 인터넷에 있는 모든 부정확한 주장을 자동으로 탐지할 수 있다는 의미는 아니다.

기존 M1의 오래된/작성일 미확인 후기 허용은 이 정책으로 대체됐다. 과거 실행 기록의 2018년 인용은 역사적 검증 결과로 보존하며 현재 자료로 재사용하지 않는다. 자료 기준일/등록 연계일과 수집일의 구분·갱신은 [데이터 관리](data-maintenance.md)를 따른다.
