# M2 교통·동선 첫 범위

등록 버스정류장까지의 **직선거리**를 조회하고 장보기 조건과 함께 개인 가중치로 비교한다. 현재 진주 정류장 1,968개 전체를 이용한다. 지도 예시와 수동으로 고른 지점은 실제 주택 매물·자동 생활권 추천을 뜻하지 않는다.

## 자료와 현재성

- [국토교통부 전국 버스정류장 위치정보](https://www.data.go.kr/data/15067528/fileData.do), 정보수집일 `2025-10-31`, 연간 갱신 자료. 공식 메타데이터를 2026-09-30 다시 확인했다. 다음 등록 예정일은 `2026-10-30`이며 실제 게시 완료일을 보장하지 않는다.
- 공식 설명은 수집일 이후 변동이 반영되지 않았다고 명시한다. 자료 날짜를 조회 날짜로 덮어쓰지 않는다. 새 공개본 및 시연·제출 고정 전 갱신 여부를 확인하는 TODO다. 이번 단계에서 새 원본을 다운로드하거나 자동 갱신을 예약하지 않았다.
- 공식 위도·경도 정의는 WGS84다. 현재 구현은 반지름 6,371,008.8m 구면 Haversine 거리이며 도로·보행 경로를 계산하지 않는다.
- 진주 행정명으로 선별한 전체 목록이다. 좌표 검사창은 위도 34.9~35.5 / 경도 127.8~128.5이며 실제 행정경계 포함 판정이 아니다. 인접 시군 정류장은 조회에 포함되지 않는다.
- 정류장 ID·명칭·좌표·정보수집일·원본 CSV 행 번호를 보존한다. 이름이 같아도 ID로 구분하고 가장 가까운 원본 행을 선택한다. 동률은 ID순으로 고정한다. 노선·탑승 방향·길 건너편 접근성으로 재선택하지 않는다. 주소 컬럼은 없으며 화면에서 정류장번호를 표시한다.

## 개인화와 흐름

`요청/필요 인터뷰 → 니즈·개인 거리 기준 → 메인 → living/transport 모듈 → 근거 검증·가중 계산 → 분야별 기여도·후보 비교`.

모듈 지표는 `bus_stop_straight_line_distance_m`, 단위 `m`, 적합도 방향 `lower`다. 사용자가 이상적 거리·만족도 0 거리와 중요도를 정한다. 별도 필수 최대거리는 명시적으로 선택한 경우만 적용한다. 필수조건은 중요도가 0이어도 계속 검사한다. 직선거리 기준만으로 현재 운행·통근 가능 여부를 판정하지 않는다.

이동수단·자주 가는 목적지·시간대는 `travel_mode`, `travel_destination`, `travel_time` 문맥으로 보존한다. 현 단계 거리 조회는 이 문맥으로 노선을 필터링하지 않는다. 이동수단만 보고 가중치를 자동 고정하거나 요구를 제거하지 않는다. 화면에서 버스 조건 제외를 선택하면 해당 조건의 중요도와 필수 제한을 해제하되 다른 교통 요구를 유지한다.

도보 시간/거리·목적지까지 소요시간·노선·배차 요구는 별도 니즈로 보존하고 미확인 비중으로 표시한다. 자료 없음·범위 밖·미지원 단위를 실제 0거리/0점으로 바꾸지 않는다. 기준 없는 정류장 요구는 원시 거리만 조회하고 적합도와 순위를 유보한다. 같은 근거로 중요도만 재계산할 수 있고 조건·좌표 변경은 새 비교로 조회한다.

직접 편집 초기값 300m/1,000m·교통 중요도 30은 사용자가 적용하기 전 평가 기준이 아니다. AI는 거리 기준을 임의로 만들지 않고 모르면 질문한다. 정류장은 상가 후기 조사에서 서버·화면 모두 제외한다.
