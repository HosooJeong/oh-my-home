# 공통 분석 지점 생성

2026-09-30 / `shop_grid_500m_v1`. 메인에서 만든 **같은 지점 목록**을 생활·교통 모듈에 전달한다. 실제 주택이나 매물 후보를 확보한 기능은 아니다.

## 자료와 단위

- [국가데이터처 SGIS 행정구역 통계 및 경계](https://www.data.go.kr/data/15129688/fileData.do): 2025-06-30 기준, 2025년 2분기 SHP, 무료·이용허락범위 제한 없음(2026-09-30 확인). ZIP 269,032,521바이트, SHA-256 `f1cf0f9de453ac7eaacb273f39cee52851183372b9ddfda428a967c3a670b2c6`.
- 원본 `.prj`의 UTM-K/GRS80(EPSG:5179)와 `.cpg` UTF-8을 확인했다. 시군구 `SIGUNGU_CD=38030`, 명칭 진주시, 행정동 `ADM_CD`의 같은 접두어 30개를 추출했다. **SGIS 통계지역 코드는 법정 시군구 코드와 별개**다. 다른 분야 자료와 코드를 임의로 결합하지 않는다.
- 좌표 축을 명시한 pyproj 변환으로 WGS84 경도·위도 GeoJSON을 만든다. 원본 꼭짓점을 생략·단순화하지 않는다. 시군구+읍면동 경계, 날짜·원본 SHP 행·해시를 `data/reference/jinju-boundary-2025.geojson`에 보존한다. 센서스 경계이며 현재 법적 경계·현장 측량을 확인한 것은 아니다.
- 전체 상가 19,577행의 EPSG:5179 위치를 500m 격자로 묶는다. **상가가 등록된 셀의 중심점**만 사용하고 시/읍면동 폴리곤에 포함되는지 확인한다. 상가 위치 자체를 주택 위치로 치환하지 않는다. 중심이 경계 밖인 5셀은 제외하여 30개 읍면동에 654개 지점이 생겼다. 원본 상가 중 시 경계 밖 행은 0개였다.
- 상가 등록이 없는 셀은 검색 범위에 없다. 중심점의 주택·도로·토지 용도·하천/산지·거주 가능성은 미확인이다. 500m 안의 어느 주택에서든 같은 접근성이라고 해석하지 않는다. 지점의 상가 수는 생성 근거이며 점수 지표가 아니다.

## 선별

1. 사용자가 확인한 니즈/거리 기준/중요도, 선택 읍면동(생략 시 전체), 2~6곳, 후보 간 최소 거리를 받는다. 기본 간격 1,000m는 수정 가능한 화면 초기값이다.
2. 필요한 인터뷰·미확인 거리 기준·미지원 활성 조건이 있으면 자동 선별을 중단한다. 예산·임대료 같은 조건을 무시해서 전체 추천을 만드는 기능은 없다. 0 중요도의 필수조건은 계속 적용한다.
3. 선택 범위의 동일 후보 전체를 기존 오케스트레이터에 전달한다. 분야별 기준·가중치·필수조건·출처/결측 규칙을 그대로 사용한다. 별도 LLM/검색 호출은 없다.
4. 필수조건을 통과하고 활성 조건의 점수가 모두 확인된 지점만 선별한다. 분류 충돌·근거 미확인 지점과 필수조건 탈락 수를 별도로 반환한다. 미확인 지점보다 선택 지점이 우수하다고 보장하지 않는다.
5. 개별 적합도 내림차순, 동률 ID순으로 보며 이미 선택한 후보와 사용자가 지정한 간격 이상이면 추가한다. 모든 후보 조합의 최적화를 하는 방식은 아니다. 수가 부족해도 간격·조건을 자동 완화하거나 경계 밖 지점을 추가하지 않는다.

화면에서 찾기를 누르면 성공한 새 목록이 현재 후보를 교체한다. 빈 결과·미지원/실패는 이전 목록을 보존한다. 1곳만 찾은 경우 원래 2곳 이상 비교 규칙을 유지하며 직접 지점을 추가하거나 조건을 수정할 수 있다. 수동 편집은 선별 당시 결과를 변조하지 않는다. `중요도 재계산`은 현재 목록의 동일 근거를 재사용하고, `분석 지점 찾기`는 전체 선택 범위에서 다시 선별한다.

## 재현과 갱신

원본·inventory·candidate-pool은 Git 제외다. 파생 경계와 수집/변환 코드는 저장소에 포함한다. 원본 SHA/날짜/좌표계가 바뀌면 검토를 요구한다. 상가 inventory 또는 파생 경계 해시가 달라지면 자동 찾기를 비활성화하고 수동 비교를 제공한다. 서버를 재시작하기 전에 같은 자료로 pool을 다시 만든다. 자동 갱신 일정은 만들지 않았다.

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt -r requirements-data.txt
.venv/Scripts/python tools/fetch_boundary.py --raw-dir data/raw/boundary
.venv/Scripts/python tools/prepare_candidates.py --archive data/raw/boundary/sgis-2025.zip
.venv/Scripts/python -X utf8 -m app.web
```

기존 작업공간 원본을 재사용할 때 `--archive ../work/boundary-research/sgis-2025.zip`, 지도 키는 `--env-file ../work/map-api-setup/.env`를 사용한다. `fetch_boundary.py --reuse`는 기존 ZIP 사용 사실을 manifest에 기록하고 공식 버전/권리를 다시 확인한다. ZIP의 주택 통계 CSV는 이번 비용 분석에 사용하지 않았다.

전처리 의존성 [PyShp 3.1.6](https://pypi.org/project/pyshp/), [pyproj 3.7.2](https://pyproj4.github.io/pyproj/stable/api/transformer.html), certifi 2026.7.22를 별도 `requirements-data.txt`로 고정했다. 앱 실행에 새 GIS 의존성은 없다. 검증: 자동 112건, 실제 654지점 조회·가중치 변경·지역 제한·누락/필수조건·브라우저 흐름 및 390/820/1440px. 실제 주택·현장·휴대폰/LAN·사용자 효과는 미검증이다.
