# 매장 후기 조사

비교 결과의 상가/학원 중 최대 3곳을 고르면 `메인 실행 관리 → 공개 웹 검색/후기 추출 → 작성일·원문·시설명/주소 대조 → 메인 결과 화면`으로 보완 의견을 제공한다. 니즈에 정성 보완 요청이 있으면 비교 뒤 확인된 시설에서 자동으로 이어진다. 공공자료의 상호·주소와 해당 시설에 연결한 비식별 기능 질문/조건 ID·학원 과목·학령·반경을 보낸다. 개인 신상·주거 후보 좌표·전체 개인 요청은 조사 프롬프트에 넣지 않는다. 공개 질문 정리와 제한된 개인정보 패턴 검사이며 모든 비식별화를 보장하지 않는다.

첫 연결 범위는 공개 티스토리 방문 후기다. 다른 사이트와 카카오·네이버 지도 리뷰 수집은 연결하지 않았다. 지도 버튼은 외부 검색 링크다. 원문에 접근할 수 없거나 검색 결과가 없으면 인용을 만들지 않는다. 개별 매장의 영업시간·휴무·폐점 여부를 조사하지 않는다.

자동 보완은 생활과 교육 각각 모델 호출 최대1회·시설 최대3곳이며 서로 다른 원래 조사 질문을 보낸다. 수동 선택은 기존 최대3곳/1회를 유지하고 원래 요청 질문이 있으면 함께 전달한다. 연결할 대상을 확인하지 못하면 범용 후기로 대체하지 않는다. 시설당 문구 최대2개다. 같은 출처의 직접 인용은 총 20단어·문구당 160자 이내로 제한한다. 중복 요청은 재실행하지 않고 전체 AI 작업은 동시에 1개다. 모델은 기존 120초 제한, 원문은 최대 6개·robots와 본문 각각 5초 네트워크 제한·크기 제한·리다이렉트 금지다. 검색 4회 목표는 프롬프트 지시이며 강제 호출 수 제한이 아니다. 실제 `web_search_count`를 기록한다. 조사 취소 및 새 비교 시 이전 결과를 폐기한다. 중요도만 바꾸면 같은 후기를 유지한다.

인용은 robots 접근 가능 여부와 공개 HTML 문구·시설명·공공 도로명주소·실제 작성일 메타데이터를 프로그램으로 대조한다. 작성 730일 초과/미래/작성일 미확인/복수 게시일 충돌·협찬/체험단 표시·다른 지점·검색 요약/원문 접근 실패는 제외한다. 수정일을 작성일로 쓰지 않는다. 전체 HTML은 저장하지 않는다. 이런 대조는 모든 의견의 진실성·현재 상황·독립성을 보장하지 않는다. 인용은 일부 개인 경험이며 전체 평판·별점·면적 수치나 정량 점수로 변환하지 않는다. [공통 정책](research-policy.md)이 기존 오래된/작성일 미확인 허용을 대체한다.

API: `POST /api/reviews`에 현재 `run_id`, 고유 `request_id`, 현재 결과의 `facility_ids`를 전달한다. 진행/완료/실패는 기존 `/api/jobs/<id>`, 취소는 `/api/jobs/<id>/cancel`을 사용한다. 세션 외 시설·오래된 비교·3개 초과·중복 ID는 거절한다. 실패/취소 후 재조사는 새 비교를 만든 뒤 실행한다.

갱신 대상인 상가 목록은 [자료 갱신 메모](data-maintenance.md)를 따른다. 조사 응답/후기는 세션 메모리에만 보관하며, 검증용 응답은 개인정보 없는 시험 입력에 한해 저장소 밖에 별도로 기록했다.

R4 이후 원문 날짜/문구/지점 검사를 통과한 최대6인용을 [별도 Codex 검토](response-validation.md)1회/45초로 확인한다. 시설별 질문·과목·해석의 직접 근거를 검사하고, 검토 응답의 ID/타입/개수도 대조한다. 실패/무관/모호함이면 인용/해석을 수용하지 않는다. 실제 연결된 질문 ID만 인용에 반환하며 한 시설의 다른 질문을 자동 해결로 표시하지 않는다. 검색/검토의 메타데이터를 구분하고 추가 검색은 하지 않는다. 원문 후보0이면 검토 호출0이다. 원문 문맥이나 거절된 AI 해석을 최종 응답에 넣지 않는다. 모든 세부 니즈 충족/전체 평판의 검증을 뜻하지 않는다.
