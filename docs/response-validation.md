# Codex 보완 응답 검증

2026-10-01, R4. 기존 니즈 정리의 스키마·원문 ID/요구 처리 검사는 R2/R3로 유지하고, 이번에는 생활/교육·안전·취미 보완 응답의 대상·관련성·해석을 강화한다. 의미 검토는 별도 Codex 호출이며 독립된 문맥을 사용한다. 같은 모델의 또 다른 판단만으로 외부 사실의 진실성을 보증하지 않는다.

1. **형식·도구·범위:** CLI 결과를 strict typed 계약으로 검사하고 예상 시설/지역 ID와 개수, 중복/외부 ID를 대조한다. 예상 밖 도구 사용·검색을 거절하고 원시 이벤트/계정 정보는 기록하지 않는다.
2. **원문 대조:** 기존 HTTPS 제공처/robots/크기·시간/작성일730일/연속 인용·지점 상호·공개 주소 검사를 통과해야 한다. 안전은 요청한 동이 인용을 포함한 같은 문장에 있어야 하며 기사 다른 곳/다음 문장에만 있으면 유보한다. 같은 인용이 서로 다른 지역 문맥에 반복돼도 유보한다. 알려진 취미 이용형태는 인용에서 직접 확인해야 하며 대안/알 수 없는 표현은 별도 의미 검토에 맡긴다.
3. **별도 Codex 검토:** 원문 검사에 남은 후보만, 공개 대상·짧은 원문 문맥·인용·AI 해석·원래 공개 질문/조회 파라미터·이용형태를 전달한다. 검색/도구를 끄고 원문 밖의 추론을 금지한다. 다른 동/지점/과목·개인/소그룹/자율 혼동, 등록정원→반크기, 계획→완료/안전, 일부 경험→전체 만족/건강 적합성 추론을 유보한다. 긍정/부정 근거 모두 수용할 수 있으며 사용자 희망의 충족 여부와 구분한다.
4. **검토 응답 재검사:** 대상·문맥·인용·해석·질문으로 만든 claim ID를 모두 정확히 한 번 반환해야 한다. 누락/중복/외부 ID·질문 연결·추가 필드·타입/판정 모순을 거절한다. 해당 질문과 관련된 `request_ids`만 인용에 남기며 같은 시설의 다른 질문에 found 상태를 복사하지 않는다. 지원 판정 외의 인용/해석은 결과에 표시하지 않는다.

분야별 후보 최대6개에 별도 검토1회/45초/재시도0, 원문 후보가0이면 추가 모델 호출0회다. 자동 생활/교육/안전/취미 모두 요청돼 후보가 있을 때 최대4회 검색 호출+4회 검토 호출이 순차 실행될 수 있다. 원래 검색 호출120초 제한/단일 모델 슬롯·분야별 실패 격리·취소/재가중치 보호를 유지한다. 전체 작업의 새 총시간 상한을 만든 것은 아니다. 검토 제한은 호출 후 원래 runner 제한으로 복원한다.

검토 실패/시간초과/애매한 판정은 **미확인**으로 처리하고 검사 전의 AI 해석을 되살리지 않는다. 검색과 별도 검토의 안전 메타데이터를 구분해 보존한다. `response_validation`에 후보/수용 수·거절 이유·검토 메타데이터, 인용에는 검토 ID·관련 질문을 남긴다. 원문 문맥은 검토에만 사용하고 최종 응답/일반 기록에 저장하지 않는다. 새 화면은 `AI 해석` 표시와 `질문 관련 인용 확인`/`인용 없음`/`응답 검토 실패`만 추가한다.

시설 존재와 조건 적합성을 구분한다. 취미의 지점/주소/종목은 확인됐지만 요청 형태/해석이 불일치하면 발견 후보는 남기고 인용 없이 `request_unverified`로 반환한다. 날짜 없는 운영자 발견 후보도 최신 이용 근거로 승격하지 않는다. 생활의 알려진 의류 브랜드와 장보기 업종 충돌은 공개 등록자료의 검토 큐에 남기고 점수/순위를 유보한다. 실제 업종이나 현재 운영 여부를 모델로 덮어쓰지 않는다.

모든 단계의 결과는 정성 보완이며 점수·필수조건 통과·순위에 자동 반영하지 않는다. 인용은 질문 일부와 관련될 수 있고 모든 세부 조건 충족을 뜻하지 않는다. 문장/이용형태의 보수적 로컬 검사와 별도 모델 판정은 모든 의미 오류·최신 상태/원문 자체의 허위·완전한 비식별화를 검출한다는 보장이 아니다.
