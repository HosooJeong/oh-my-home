# 선호 중심 인터뷰

2026-10-03. 제품 호출은 기존 `gpt-6.1-sol`·`medium`을 유지한다.

사용자에게 거리·직선반경·충분한 개소 수·만족도 0·퍼센트를 계산하게 하지 않는다. 이미 말한 가까움/타협/상대 중요도는 그대로 보존하고, 학교급·과목처럼 실제 조회에 필요한 정보만 짧은 존댓말 질문과 최대3개의 답변 문장으로 확인한다. 버튼은 답변란에 문장을 넣고 자유 편집을 유지한다. 숫자를 직접 말한 경우에는 원문 수치/단위와 명시 필수조건을 보존한다.

모델은 명시되지 않은 거리/개소 곡선을 `utility=null`, 학원 반경은 생략으로 반환한다. 상대 중요도는 제안값으로 유지한다. 원문 연결 검증 후 앱이 지원하는 정량 지표에만 `comparison_proposal`을 붙인다. 수치가 없는 선호를 필터나 필수조건으로 만들지 않는다. 모델이 임의로 출력한 수치에는 기존 원문 검증을 적용하며, 제안값을 사용자 숫자 원문으로 허위 연결하지 않는다. 다음 인터뷰에서도 이전 앱 제안을 사용자 수치로 재해석하지 않는다.

| 앱의 비교 제안 | 내부 계산 기준 |
|---|---|
| 집 바로 가까이에 있으면 좋아요 | 해당 시설의 원문 구절에서 코앞/바로 앞/바로 가까이/아주·매우 가까움이 확인된 경우 직선거리 100m/800m |
| 가까우면 좋아요 | 직선거리 300m까지 충족, 1500m에서 기여0 |
| 조금 멀어도 괜찮아요 | 해당 단일 need에서 타협이 확인된 경우 600m/2500m |
| 학원 선택지가 다양하면 좋아요 | 등록 선택지3개소까지 충족,0개소에서 기여0; 반경 미지정 시 직선1500m 조회 |

이는 서비스가 정한 첫 제안이며 공인 기준·실제 도보 시간·학원 품질·사용자 직접 지정 한계가 아니다. 알려진 직선거리·등록 개소의 선호 충족도만 비교한다. 학교급/과목이 없는 학원, 자료 누락/오래됨/학령 미확인, 실제 이동/품질 같은 미지원 요구는 기존 미확인 정책을 유지한다. 도보·차량 API와 분석 연결 범위를 확대한 것은 아니다. 일부 수치가 이미 지정됐거나 필수조건이 있으면 이 기본값으로 덮지 않는다.

메인 조건 확인과 결과에는 생활 선호와 `비교 기준 제안`을 보여준다. 정확한 곡선·학원 조회 반경은 조건 확인의 접힌 `원문과 기준`에서 확인할 수 있다. 확인 버튼은 제안 비중을 승인해 기존 순위 계산을 허용한다. 최초 제안값은 `importance_proposal`로 따로 보존하고, 다음 인터뷰에서 숫자를 직접 답하지 않았다면 승인값을 원문 수치처럼 재해석하지 않는다. 사용자가 수치를 수정해 제안의 스냅샷과 달라지면 제안 라벨을 적용하지 않는다.

관련 확인은 Python `test_intuitive_intake`, `test_source_bindings`, `test_need_coverage`, `test_intake_flow`, `test_codex_runner`와 Node `analysis-view.test.mjs` 및 실제 프론트엔드 인터뷰로 구분해 기록한다. 일부 대표 질문의 실제 성공을 모든 자연어/카테고리의 보장으로 표현하지 않는다.
