# 상가 자료 갱신 메모

2026-09-30 사용자 확정: 상가(상권)정보의 **영업 중인 업소 목록**을 기본 자료로 쓰고, 지속적으로 갱신해야 한다는 관리 항목을 남긴다. 개별 상가의 영업시간·휴무 요일 조사나 별도 운영·폐점 판정 기능은 현재 범위에 넣지 않는다. 에이전트의 보완 역할은 공개 후기에서 규모·품목·만족/불만족 의견을 짧게 인용하고 출처를 연결하는 것이다.

- [공식 자료](https://www.data.go.kr/data/15083033/fileData.do): 확인일 2026-09-30, 현재 확보 파일 **2026-06-30 기준**, 공식 갱신 주기 **분기**, 차기 등록 예정일 **2026-10-31**로 표시. 예정일은 변경될 수 있으므로 제공처에서 다시 확인한다.
- **TODO: 새 분기 파일이 공개되면 갱신한다. 시연·제출 버전을 고정하기 전에도 새 자료 공개 여부를 확인한다.** 아직 자동 갱신 작업이나 예약 실행은 만들지 않았다.
- 새 원본은 이전 파일을 덮어쓰지 않는 별도 폴더에 받고, 제공처·버전·조회일·SHA-256을 남긴다. `tools/fetch_public_data.py --raw-dir <새 폴더>`와 `tools/build_samples.py --raw-dir <새 폴더>`가 기본 도구다. 수집기는 현재 3종 자료를 함께 받으므로 필요한 갱신 범위를 먼저 확인한다.
- 분기 변경 시 `build_samples.py`의 버전/표본 검증을 검토한다. 진주 행 수, 좌표 오류, 업종 분포, 삭제·추가된 ID와 표본 상가 변경을 확인한다. 목록에서 빠졌다는 이유만으로 개별 폐업을 확정하지 않는다.
- 검사 후 정규화 자료를 교체하고 서버를 재시작해 이전 비교 세션과 혼용하지 않는다. 결과의 자료 기준일, 검증 증거와 코드 버전을 함께 갱신한다. `--reuse`는 원본 재사용이며 최신 파일 다운로드가 아니다.

분기 자료에 포함됐다는 사실은 조회 시점의 현장 영업을 실시간 보장하지 않는다. 이 갱신 과제를 별도 폐점 조사 기능이나 모든 시설 확인 완료로 표현하지 않는다.

## 공통 분석 지점 자료 후속 (2026-09-30)

진주 센서스 경계는 SGIS 2025-06-30 기준을 고정했다. [공식 자료](https://www.data.go.kr/data/15129688/fileData.do)와 [준비 절차](candidate-generation.md)를 따른다. 경계/상가 inventory 해시가 바뀌면 pool을 재생성하고 경계 포함·행정코드·지점 수를 검토한 뒤 서버를 재시작한다. 중심점은 실제 주택/거주 가능성 근거가 아니다. 새 경계·분기 상가 갱신 및 자동 일정은 후속으로 남긴다.
