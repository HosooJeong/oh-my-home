# 결과를 생활 선호와 연결해 설명하기

2026-10-03. `app/static/result-report.mjs`의 결과 문장은 확인한 시설·측정값과 조건별 선호 충족도를 함께 설명한다. 총평은 현재 선택한 집에서 중요도가 높은 확인된 항목 두 개까지 보여준다. 분야별 탭은 설명을 먼저 보여주고 수치/충족도를 보조 정보로 남긴다. 원문·비교 기준·출처는 기존 접기에서 확인한다.

## 사실과 해석

- 편의점·마트·정류장·학교·공원·도서관: 해당 집/조건에 연결된 근거의 `source_record`와 시설 `id`가 일치할 때만 시설 이름을 넣는다. 등록 위치의 직선거리와 개인 선호 곡선에 따른 평가를 설명하며 실제 도보 거리나 차량 소요시간으로 바꾸지 않는다.
- 약속 장소: 사용자가 지정한 지점으로 설명한다. 등록시설 중 최근접 장소라는 표현을 쓰지 않는다.
- 학원: 확인된 전체 개소 수일 때만 과목/학교급·직선반경·선택지 수와 일부 시설 예시를 설명한다. 불완전한 등록 목록은 전체 개소 수나 만족도 확정으로 표현하지 않는다. 등록 선택지가 많다는 사실을 수업의 질·현재 모집 여부로 해석하지 않는다.
- 자료 누락/충돌·조회 실패·평가 미지원은 미확인으로 유지한다. 가격 참고 자료를 집별 예산 충족이나 매물 추천으로 바꾸지 않는다.

곡선이 앱 제안일 때 그 출처는 기존 `comparison_proposal`로 유지한다. 조건 확인 후의 평가 표현이 사용자가 숫자 목표를 직접 말한 사실을 만들지는 않는다. 점수·분야 비중·후보 순위·필수조건·사용자 원문·인용·모델 반환 원문은 변경하지 않는다.

## 예시와 경계

“등록자료에서 가장 가까운 씨유 시험점까지 집에서 직선거리 220m예요. 편의점이 가까운 생활을 원하는 선호에 잘 맞는 위치예요.”처럼 사실과 평가를 연결한다. 시설 이름/거리는 해당 결과에서 읽으며 문장 안의 예시는 실제 이용·운영을 보장하지 않는다.

실제 이동 경로·시간과 현재 영업 등은 분야별 확인 범위에 짧게 표시한다. 별도 `/routes`의 실시간 카카오 도보/대중교통 조회와 생활 점수는 아직 분리돼 있다. 이번 변경은 경로 API/차량 API 연결이나 경로 응답의 LLM 전송을 추가하지 않는다. 추가 제품 LLM 호출 없이 기존 검증 결과로 문장을 만든다.

## 검증

`node --test tests/result-report.test.mjs tests/analysis-view.test.mjs`는 이름/근거 연결·직선거리 유지·타협 선호·부분/0 충족·자료 미확인·학원 범위와 개소 수·총평의 집별 선택·기존 점수/차트 계산을 검사한다. 실제 화면 검증과 종료 코드 버전은 프로젝트 기준 기록의 `FRIENDLY_REPORT01`에 연결한다.
