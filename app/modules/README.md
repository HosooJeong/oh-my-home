# M1 생활·건강: 장보기 접근성

M4 `EducationModule`도 같은 `CategoryResult` 규격으로 등록했다. 학교 직선거리/학령·과목·반경별 학원 개소 수를 반환하고 누락/오래된 자료는 점수 유보한다. 등록정원/실제 반 크기·최근접/배정·직선거리/통학로를 구분한다. 자세한 매개변수·준비/한계는 [교육 모듈](../../docs/education-accessibility.md)을 따른다. 조건부 웹 보완은 공유 호출기/정책을 통해 메인 작업 관리로 합쳐지며 정량 근거와 별도다.

`LivingModule`을 메인 `Orchestrator`에 `living`으로 등록한다. 모듈은 전역 가중치를 수정하지 않고 근거를 반환한다. 현재 메트릭:

| metric | 대상 | 값 |
|---|---|---|
| `grocery_straight_line_distance_m` | 슈퍼마켓 업종 중 편의점 브랜드 제외 | 가장 가까운 원본 행까지 직선거리 m |
| `convenience_straight_line_distance_m` | 편의점 업종 | 같은 방식 |
| `house_to_grocery_straight_line_distance_m` | P0 인터뷰의 명시적 직선거리 호환명 | 첫 지표와 동일 |

생활 모듈은 `lower`/`m`만 평가하며 도보 분이나 임의 지표를 자동 변환하지 않는다. 기준이 아직 없으면 원시 거리를 조회하고 적합도는 미확인으로 둔다. 자료가 없거나 좌표 검사 범위 밖이면 `missing`, 명칭·업종의 충돌이 의심되면 `conflicting`으로 반환한다. 최근접 충돌 행을 건너뛰어 다른 시설을 확정 답으로 만들지 않는다. 서버의 공통 평가기가 기존 비중을 유지하며 총점/순위 유보를 결정한다.

전체 진주 상가 19,577행을 불러와 원본 소분류명으로 조회용 목록을 만든다. 좌표를 수정하지 않고 반지름 6,371,008.8m 구면의 Haversine 거리(소수 3자리 m)를 계산한다. 실제 지리 기준계·입구 좌표·도로/보행 동선의 정확성을 새로 검증한 것은 아니다. 34.9~35.5 / 127.8~128.5 범위는 이상 좌표 검사창이며 진주 행정경계 판정이 아니다.

`name_conflict_v1`은 전자담배 상호와 슈퍼마켓 브랜드 접두어 일부를 탐지하는 보수적인 검토 규칙이다. 원본·ID·업종을 보존한다. 실제 현재 업종 확인이나 모든 오류 탐지를 보장하지 않는다. 별도 반경 시설 수·의료·약국은 후속이다. 개별 운영시간/휴폐업 판정은 사용자 D18에서 제외했다. 거리 모듈의 수치와 비교 문장은 결정적 계산/표시이고 니즈 해석과 별도 공개 후기 조사에서 실제 LLM을 사용한다.

새 카테고리는 `CategoryModule.run(ModuleRequest, Event)` 규격을 구현하고 `AppState`의 레지스트리에 추가한다. 다른 분야의 요구를 생활 지표로 치환하지 않는다. 단위·출처·시점·후보/조건 식별자와 요청 지문을 보존해야 한다.

## M2 교통·동선: 정류장 접근성

`TransportModule`을 `transport`로 등록한다. `StopIndex`는 inventory의 `kind=bus` 전체 1,968행을 읽는다. `bus_stop_straight_line_distance_m` 하나를 지원하며 가장 가까운 원본 정류장까지 `lower`/`m` 근거를 반환한다. 생활·교통 모듈은 공통 `app.geo`의 좌표 검사창·Haversine 계산을 사용하고 각자 자료·ID·시점을 관리한다. 가중치와 순위는 공통 평가기에서만 계산한다.

ID·좌표·출처·날짜·CSV 행을 검사한다. 자료 없음·좌표 검사창 밖은 missing, 도보/통근시간·단위/방향 불일치는 unsupported로 반환한다. 이름이 같은 정류장을 합치거나 노선/방향을 추측하지 않는다. 자료·사용자 편집·미지원 조건의 세부 경계는 [교통 범위](../../docs/transport-accessibility.md)를 따른다. 공통 후보 자동 생성은 별도 후속이다.
