# oh-my-home

살자리: 개인의 생활맥락을 이해하는 주거 의사결정 AI Agent.

현재는 **니즈/인터뷰·개인 가중치·최소 오케스트레이터(P0)**, **장보기 직선거리·공개 후기(M1)**, **정류장 접근성(M2)**, **공통 분석 지점 선별**, **아파트 실거래 참고 분포(M3)**, **학교·과목별 학원 접근성(M4)**, **CCTV 참고/문제별 공식 보완(M5)**, **목적별 공원·도서관/지정 지점 접근성과 사설 취미시설 발견(M6)**의 첫 범위를 구현했다. 같은 후보를 개인 기준으로 비교하며, 공공 근거를 먼저 계산하고 필요할 때 구독 인증 LLM이 공개 웹을 직접 검색해 보완한다. 작성일·원문·동일 시설의 이름/주소를 대조한 짧은 인용을 점수와 분리한다. 집값은 점수 반영 0의 참고 분포이며 실제 매물 추천은 없다. 의료·실제 경로·정량 위험/환경·모임/프로그램 등 자료 공백은 후속이다. Python과 정적 HTML/JavaScript를 사용한다. 첫 화면은 Three.js 블록 마을이며 `/analysis`에서 자동 니즈 정리·인터뷰·지도 결과를 연결한다. 기존 `/workspace`는 상세 편집 화면으로 남아 있다.

10/1 **나의 생활 마을과 분석**: 주소 없는 탐색/집 한 곳/여러 집의 3개 진입점, 1~6개 블록 배치·거리 중요도, 선택 분야 상세 입력→자동 니즈 정리/필요 인터뷰→탐색 또는 지도 위치 선택→결과를 연결했다. 집 한 곳 결과에서 주변 비교를 추가한다. 집·비용은 참고/점수0이며 미확인 비중을 유지한다. 집 위치는 지도 클릭/좌표 입력으로 지정하고 주소 자동 변환은 없다. [새 분석 흐름·계약·범위](docs/analysis-flow.md), [3D 조작](docs/village-builder.md), [Three.js MIT 출처](THIRD_PARTY_NOTICES.md).

10/1 **배치 화면 개선**: 화면을 넓게 사용하고 집/카테고리가 더 크게 보이도록 조정했다. 중앙 집을 두꺼운 돌기 벽돌·경사 지붕 부품·창틀/현관·굴뚝/계단으로 다시 조립하고, 블록의 들기/놓기 반응을 다듬었다. 신규 외부 3D 자산은 없다. 기존 선호 검사9개·8객체 geometry smoke·실제 드래그/회전/상세 전환·1280/820/390px 화면을 확인했다. 실제 휴대폰/정량 성능 검증과 구분한다.

M6는 공원182/도서관74곳과 사설 취미 등록 후보·LLM 직접 웹 발굴을 연결한다. 공원 유형·도서관 유형·종목/이용 형태·개인 중요도를 보존한다. 도서관73곳의 오래된 행과 취미 적합성은 점수를 유보하며 미확인 비중을 유지한다. 웹 발견/일부 경험을 점수나 필수조건 통과로 승격하지 않는다. [여가 자료·재현·범위](docs/leisure-accessibility.md). 변경 관련 핵심82건·실제 니즈/웹검색·브라우저/취소/재가중치를 확인했다. 실제 취미 검색의 수용 후보는0곳이며 실제 인용 확보·전체6분야E2E 완료와 구분한다.

M4는 진주 학교 90곳과 학원·교습소 1,222개소를 연결했다. 필요한 학교급·과목·반경·충분한 선택지 수와 가중치를 입력한다. 학원은 위치 미연결 215개소, 오래된 NEIS 연계일 761개소 등이 있어 완전한 수/점수를 확정하지 않는다. 학교 배정·통학로 안전·실제 반 크기는 미확인이다. [교육 자료와 재현](docs/education-accessibility.md), [전체 보완 조사 원칙](docs/research-policy.md)을 따른다. 변경 관련 핵심 검사 49건·실제 니즈/직접 웹검색·단일 브라우저 흐름을 확인했고 모든 분야/웹 제공처 완성을 뜻하지 않는다.

P0의 설치·실행·모듈 계약·한계는 [Agent 코어 안내](app/README.md)를 따른다. 아래 지도 표본 실행은 기존 방식대로 사용할 수 있다.

M3는 2025-09~2026-08 진주 아파트 매매 4,459건·전세 2,198건·월세 2,440건(해제 매매 280건 제외)의 건수·중앙값·가격 편차를 조회한다. 거래 방식/법정동 주소/면적/임대 계약 구분을 선택하고, 표본 5건 미만은 요약을 유보한다. 법정동 가격을 지도 후보 가격이나 예산 충족 근거로 쓰지 않는다. [집·비용 범위와 원본 준비](docs/housing-reference.md)를 따른다. 자료가 없어도 생활·교통 비교는 유지된다. 이번에는 M3 핵심 검사 8건+공통 코어 23건과 단일 브라우저 흐름만 확인했으며 전체 120건 재실행·반응형 반복·신규 제품 모델 호출은 하지 않았다.

## 생활권 비교 앱 실행

아래 원본 확보·선별 단계를 거쳐 `data/processed/inventory.json`을 준비한 다음 실행한다.

~~~powershell
python -m pip install -r requirements.txt
python -X utf8 -m app.web
# 기존 작업공간의 키를 사용할 때
python -X utf8 -m app.web --env-file ../work/map-api-setup/.env
~~~

http://localhost:5173 에서 마을 배치를 시작한다. 기존 분석은 http://localhost:5173/workspace 에서 AI로 조건을 정리하거나 거리·중요도를 직접 입력한다. 새 화면은 집 한 곳 또는 2~6곳을 지도 클릭/좌표 입력으로 선택한다. 거리 기준 변경은 새 비교, 중요도만 변경하면 같은 근거로 재계산한다. AI 경로에는 ChatGPT로 로그인한 Codex CLI가 필요하며, 직접 입력·거리 비교는 모델 없이 동작한다. 기존 표본 지도는 `/samples`에서 열린다.

마트는 원본 슈퍼마켓 업종 542행 중 편의점 브랜드 접두어 3행을 제외한 539행, 편의점은 원본 업종 335행을 대상으로 한다. 상호에 전자담배가 포함되거나 편의점 업종에 슈퍼마켓 브랜드가 나타나는 4행은 충돌 의심으로 보존한다. 이런 행이 최근접이면 거리는 제시하되 점수와 전체 순위를 유보한다. 이는 제한적인 품질 탐지 규칙이며 나머지 시설의 업종·신선식품 재고·영업을 모두 확인했다는 뜻이 아니다. 진주 자료만 비교하므로 인접 시군의 더 가까운 시설이 누락될 수 있다.

출처·원본 행·자료 기준일·계산 시각을 결과에 표시한다. 도보 시간, 버스 통근시간, 노선·배차·현재 운행이나 의료 근거는 추정하지 않는다. 지원하지 않는 조건도 유지하고 미확인 비중을 점수 범위에 남긴다. 범위는 통계적 신뢰구간이 아니다.

교통 조건은 AI 니즈/인터뷰 또는 조건 정리 후의 **교통 조건 확인·수정**에서 입력한다. 이동수단·목적지·시간대를 보존하며, 원하는 경우 등록 정류장 직선거리를 평가에 추가한다. 거리 기준·필수 최대거리·교통 분야와 정류장 조건 중요도를 직접 확인할 수 있다. 분야별 비중과 확인된 점수 기여도를 함께 표시한다. 자차 이용만으로 버스 조건을 지우지 않고 사용자가 정류장 평가를 제외하면 중요도와 그 조건의 필수 제한만 해제한다. 정류장은 후기 조사 대상에 포함되지 않는다. [교통 자료·평가 범위](docs/transport-accessibility.md)를 따른다.

사용자 확정 범위: 상가 목록은 영업 중 업소의 분기 자료를 사용하고 **지속 갱신 필요사항만 관리**한다. 개별 영업시간·휴무 요일·운영/폐점 판정 기능은 만들지 않는다. [자료 갱신 메모](docs/data-maintenance.md)에 현재 기준일과 갱신 절차를 남겼다.

비교 후에는 최대 3개 상가의 공개 후기를 조사할 수 있다. 현재 공개 티스토리 글을 연결하며 출처·작성일·짧은 인용·AI 해석을 구분한다. 작성일이 오래됐거나 원문 문구를 확인할 수 없는 경우를 표시한다. 후기 일부를 전체 평판으로 일반화하거나 거리 점수에 넣지 않는다. [후기 조사 범위와 제한](docs/review-research.md)을 따른다.

로컬 개발 서버는 `0.0.0.0:5173`에 바인딩한다. 같은 네트워크에서 사용하는 시제품이며 인터넷 공개용 사용자 인증은 없다. Host는 localhost/IP만 허용하고 POST는 동일 Origin·세션 토큰·JSON 크기를 검사한다. 앱 세션은 메모리에만 보관하고 1시간 미사용 시 다음 접근에서 만료 처리한다(서버 종료 시 소멸). 모델 작업은 동시에 1개, 요청 ID별 중복 방지·취소·120초 제한을 적용한다. 브라우저에 API 비밀키나 원시 CLI 오류를 보내지 않는다.

10/2 테스트 대화 저장: `python -B -X utf8 -m app.web --env-file ../work/map-api-setup/.env --debug-transcripts`로 실행하면 `../work/saljari-private/debug-sessions/YYYYMMDD-HHMMSS-식별자.txt`에 UTF-8로 기록한다. 진입/확정한 후보·카테고리 질문과 답변·인터뷰·모델에 보낸 프롬프트·실제 최종 반환(검증 실패 포함)·작업 시각/오류 코드·경과 시간/검증 위치·비교 결과를 같은 브라우저 세션의 한 파일에 이어 쓴다. 재시도/화면 이동 시 같은 세션을 사용하며 서버 재시작·만료 뒤에는 새 파일을 만든다. 인증값/세션 토큰과 CLI reasoning 이벤트는 기록하지 않는다. 개인 입력이 들어가는 로컬 테스트 자료이므로 코드 저장소 밖에 둔다. 원시 stderr/내부 추론은 저장하지 않고, 크기 제한을 넘긴 반환은 오류만 남긴다. 옵션을 빼면 저장하지 않는다. 이미 소멸한 이전 실패 원문을 복원하는 기능은 아니다.

집 한 곳은 후보 1곳, 여러 집은 후보 2~6곳을 카카오 주소 검색/지도 또는 대체 좌표 입력으로 먼저 확정한 뒤 블록 배치로 넘어간다. 주소 없이 탐색은 후보 입력 없이 시작하며 생활권 입력은 선택이다. 확정한 후보의 좌표/식별자를 조건 입력과 비교까지 보존하며 집 주소를 모델의 니즈 해석 프롬프트에 넣지 않는다. 주소 변환은 [카카오 공식 예제](https://apis.map.kakao.com/web/sample/addr2coord/)의 services 라이브러리를 사용한다. 분석 자료 범위는 기존 진주 공공자료이며 개별 주택 매물 추천은 하지 않는다.

## 실행

9/30 공통 후보 후속: 공식 2025년 진주 시/30개 읍면동 경계와 **상가가 등록된 500m 격자 중심 654개**를 연결했다. 지역·개인 거리 기준·분야 중요도·필수조건·후보 간격으로 2~6곳을 선별하며 같은 목록을 생활·교통에 전달한다. 미지원 활성 조건은 선별을 중단하고, 근거 미확인/필수조건 탈락 수를 표시한다. 실제 주택·도로·거주 가능성이 확인된 후보는 아니다. 자동 112건·실제 자료/브라우저·390/820/1440px를 확인했다. [자료 준비·알고리즘·범위](docs/candidate-generation.md)를 따른다. 앞의 후보 자동 생성 미구현은 M2 첫 범위 당시 이력이다.

Python 3.11 이상이 필요하다. 아래 명령은 저장소 루트에서 실행한다.

1. 공식 원본을 내려받는다. 상가 전국 ZIP은 확인 당시 약 353 MB다.

~~~powershell
python tools/fetch_public_data.py
~~~

2. 진주 행을 선별하고 품질 결과와 지도 표본을 만든다.

~~~powershell
python tools/build_samples.py
~~~

3. .env.example을 .env로 복사하고 카카오 **JavaScript** 키를 설정한다. 허용 도메인에 http://localhost:5173 을 등록한 뒤 실행한다.

~~~powershell
python tools/preview/server.py
~~~

http://localhost:5173 에서 연다. 기본 바인딩은 0.0.0.0이다. 다른 장치 접속은 해당 주소의 카카오 SDK 도메인 설정과 별도 확인이 필요하다.

기존 AIcontest 작업공간의 원본과 키를 재사용할 때:

~~~powershell
python tools/fetch_public_data.py --raw-dir ../work/dataset-samples-20260929/raw --reuse
python tools/build_samples.py --raw-dir ../work/dataset-samples-20260929/raw
python tools/preview/server.py --env-file ../work/map-api-setup/.env
~~~

--reuse는 기존 파일 재사용을 manifest에 명시한다. 새 자료를 확인할 때는 새로운 raw 폴더로 내려받아 비교한다. 원본 파일·정규화 전체 자료·키는 Git에서 제외한다.

## 생성 파일

- raw/manifest.json: 제공처·버전·공식 다운로드 URL·조회 시각·파일 크기·SHA-256
- processed/inventory.json: 진주에서 좌표 범위 검사를 통과한 행
- processed/quarantine.json: 좌표 오류 의심 행과 수정하지 않은 원문
- processed/quality.json: 진주 행 수·좌표·주소·중복·자료 시점 점검
- processed/preview.json: 충무공동·가호동·평거동 주변의 27개 지도 표본

기본 위치는 data/ 아래이며 경로를 인자로 바꿀 수 있다. 지도 화면은 지역 전환, 유형 필터, 목록/마커 선택, 원문 출처와 자료 시점 표시를 지원한다. 지도 표본 화면은 카카오 Local/REST API나 GPT에 장소 자료를 보내지 않는다. P0의 실제 모델 확인에는 합성 니즈 입력과 공식 Codex 문서 검색만 사용했다.

CCTV 3행은 위도 32.216844로 진주 주변 범위를 벗어나므로 제외했다. 35도로 임의 보정하지 않는다. 나머지 CCTV 행에는 완전히 같은 내용의 추가 행 1,314개가 있지만, 여러 카메라 표현 여부가 불명확하므로 원본·정규화 자료에서 삭제하지 않는다. 지도 표본에서만 같은 좌표 중복을 피한다.

좌표 검사는 넓은 주변 범위(위도 34.9~35.5, 경도 127.8~128.5)의 이상값 탐지다. 정확한 행정경계 포함·각 지번의 위치 정확성·현재 영업·버스 운행·CCTV 작동 검증은 아니다. 별도 행정경계 자료를 사용하지 않았다. 위도/경도를 Kakao LatLng에 그대로 표시해 비교하며 원본의 지리 기준계 명세 전체는 미확인이다.

상가 자료의 분기와 표본 기준 상가 ID는 이번 검증 버전에 고정했다. 다음 분기 자료로 바뀌면 자동 추정하지 않고 build_samples.py가 재검토를 요구한다. 기준 상가는 지리적 표본 선택용이며 추천 매장이나 주택 후보가 아니다.

## 검증

~~~powershell
python -m unittest discover -s tests -v
~~~

기존 데이터 검사 6개는 좌표 오류/NaN/빈 값, 원본 보존, 지역 필터, 표본 거리 제한, 실제 표본과 정규화 원본의 일치를 확인한다. 원본 기반 검사는 processed 자료 생성 후 실행한다. 추가 P0 검사는 개인 가중치·필수조건·근거 누락·모듈 통합·재평가·CLI 오류/취소를 확인하며 `requirements.txt` 설치가 필요하다. 자동 검사에서 모델 호출은 하지 않고 실제 호출 증거와 구분한다.

실제 브라우저에서 3개 지역·종류별 표본·필터·목록/마커 선택·빈 필터·로드 실패/복구·390/820/1440px 화면을 확인했다. 지도 SDK 내부 부동소수점 변환을 고려해 원본과 마커 좌표 비교 허용 오차는 1e-9도다. 개발 데이터 표본 검증이며 Agent E2E 또는 실제 휴대폰 검증은 아니다.
